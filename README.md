# 砰砰机器人

一个跑在真实 QQ 群里的群聊机器人。**2022 年开始写，至今持续维护**——从一份三百行的轮询脚本，
长成现在的插件化框架：**21 个功能，服务 270+ 活跃用户，长期在线运行。**

> 2022–2026 的早期版本没有纳入本仓库。其中三代的入口文件存档和逐条对比见
> [`legacy/`](legacy/README.md)。

```
   NapCat（QQ 协议端）
          │  HTTP POST 事件
          ▼
     main.py ············· FastAPI 入口
          ▼
   bot/core.py ··········· 按优先级逐个询问插件，取第一个接手的
          ├── bot/plugins/      21 个功能
          ├── ai_core/          检索问答 + 联网 agent
          ├── roulette/         轮盘对局（含自己训练出的 AI 对手）
          └── rabble/           乌合之众
          ▼
    output.py ············ 全项目唯一的发送出口
```

## 它能做什么

- **问群里的旧事** —— @它问「之前群里聊过 XX」，它会翻群聊记录回答；答不上就直说答不上
- **和 AI 对话** —— `%问题` 直接问，`%%问题` 让它先联网搜再答
- **玩游戏** —— 轮盘对局（对手是一个自己训练出来的 AI）、乌合之众
- **日常小功能** —— 骰子、漂流瓶、自定义词条、梗图、群聊记录、复读、喵卡周赛查询、吃什么推荐

## 几处设计取舍

最早它是个三百行的脚本：一个 `while True`，所有功能挤在一棵 if/elif 树里，
状态全是模块级全局变量。加一个功能要在好几处同时改——私聊一份、群聊一份，
还得记得 import；漏一处那个功能就没了，而且不报错。现在是插件框架：
新建一个文件、在清单里加一行声明，漏了那一行，程序启动直接报错。

（清单校验是后补的。在那之前真漏过一次——某个功能的提示连续几个版本都发不出来，
没人发现。）

框架一共重写过四代，起因基本都是上一代的设计缺陷。最典型的一个：
早期用一个布尔变量同时表示"这条消息我接了"和"允许我回复"，
导致"接了但不回复"这种状态根本表达不出来——忘了设那个变量，消息就静默丢掉。
第四代把这个布尔拆成三个明确的返回值，这种状态就从"容易写错"变成了"写不出来"。
三代的入口文件都存在 [`legacy/`](legacy/README.md) 里，可以对着看。

另一件一直在做的事是把副作用收口：插件只负责算出该回什么，
什么时候发、发几条、发失败了怎么办，全归框架管。
以前这些散在几十个地方，出了问题连"到底谁发过"都查不清。

检索问答的适用范围是收窄过的，不是一开始就这么设计的。双路检索在群聊这种超短句、
没上下文的语料上提升有限——简单的题本来就能答对，难的题两条路都答不对。
所以把范围收到"问某个具体的人和事"，需要跨多条消息汇总的另开了一条 agent 通路。
评测也做了，四类失败模式记在文档里。

## 代码结构

| 目录 / 文件 | 作用 |
|---|---|
| `main.py` | FastAPI 入口，接收 QQ 协议端推来的事件 |
| `bot/` | 插件框架：分发、插件契约、配置与权限 |
| `bot/plugins/` | 21 个功能插件 |
| `ai_core/` | 检索问答与联网 agent |
| `chat_rag.py` | 检索链路的实现（被框架和 ai_core 共用） |
| `output.py` | 唯一的发送出口 |
| `token_usage.py` | 按输入输出加权的 token 配额 |
| `roulette/` `rabble/` | 两个游戏模块 |
| `legacy/` | 三代入口文件存档 |

## 关于运行

**这个仓库只有代码，clone 下来跑不起来。** 数据目录（`文档/` `json/` `database/` `图片/` 等）
在仓库之外，代码按 `../文档/` 这类相对路径引用它们；启动时还要去 NapCat 取机器人自己的账号，
没有一个在运行的 NapCat 实例就起不来。

它本来也不是一个让人 `pip install` 的库，而是一个长期在线部署的服务——
依赖和数据都以挂载卷的形式挂在外面。

需要设置的环境变量（**只列名字，值请自己填**）：

| 变量 | 是否必填 | 用途 |
|---|---|---|
| `NAPCAT_HOST` / `NAPCAT_PORT` / `NAPCAT_TOKEN` | 必填 | 连接 QQ 协议端 |
| `DEEPSEEK_API_KEY` | 选填 | AI 对话 |
| `BOCHA_API_KEY` | 选填 | 联网搜索 |
| `DASHSCOPE_API_KEY` | 选填 | 文本向量化 |
| `SUPER_ADMIN_QQ` | 选填 | 超级管理员账号 |
